# Temper — falsify-or-certify, from trained model to shipped binary

**Author: Vaishnavi** · compiler underneath: **ModelForge**

A neural network reaches a device through a chain of transformations: compiler
rewrites, hand edits, quantisation and pruning, code generation, and the C++
compiler's own optimisations. Any of them can silently change a prediction.
Tests can only say *"no bug found"*; verifiers can only say *"unknown"* when
there is a bug. **Temper gives every transformation one of three answers:**

| Verdict | What you get |
|---|---|
| **REFUTED** | a replayable input where the outputs differ, localised to the first IR value that diverges |
| **CERTIFIED** | a proof that outputs are **bit-identical** (or within ε) for *every* input in the deployment domain — sound for float32, not just real arithmetic |
| **UNDECIDED** | the share of the domain already proven, so you know what is left |

ModelForge (the C++17 model compiler in this repository) produces the
transformations and the code; Temper decides which of them can be trusted.

## Why it is useful

```bash
temper model.mforge --data test.csv          # one command, full trust report
```

* every optimisation pass **certified bit-exact or rolled back** with a counterexample;
* **compression audit**: for float16 / int8 / int4 / pruning, the worst realistic
  disagreement *found* and an upper bound *proven* — with a certified recommendation
  (e.g. Breast Cancer: int8 is *proven* low-risk; int4 keeps its test accuracy but has
  a realistic input where the original's top-two margin is 0.79 and the compressed
  model disagrees);
* **binary audit**: compiles the generated C++ under `-O0`, `-O2`, FMA and
  `-ffast-math`, replays it against the certified model, and tells you which flags
  are safe;
* generated C++ that **knows where its guarantees hold**: `in_certified_domain(x)`,
  a model fingerprint, and a per-row `in_certified_domain` column in `--csv` mode;
* `dossier.json` and exit codes for CI: `0` ship, `3` blocked (`--compare`: `0`
  certified, `3` refuted, `4` undecided).

```bash
temper reference.mforge --compare edited.mforge   # is a hand-optimised / converted copy equivalent?
```

## Results (all regenerated by `modelforge_bench`)

On **2,352 transformations** of 96 networks (2,064 injected faults, 96 negative
controls, 192 real optimisation passes):

| | observable faults refuted | benign transformations certified | all decided | evaluations / case | unsound |
|---|---|---|---|---|---|
| Guardian-APC+ (falsifier only) | 96.7% | 0% | 84.6% | 23.5 | – |
| Certifier only | 82.3% | 100% | 84.2% | 101.8 | 0 |
| **Temper** | **2,057 / 2,058** | **100% (bit-exact)** | **99.7%** | **11.3** | **0** |

* **54 faults** were exposed by no input of a 4,000-input random oracle and found
  only by **certificate-guided witnesses**: the certifier locates the units and
  value ranges where a buggy operator can act, and Newton steps solve for an input
  there.
* **Compression of 8 real classifiers** (Iris, Wine, Breast Cancer, Digits; 40
  cases): 12 certified low-risk, 25 refuted with realistic witnesses (7 of them kept
  full test accuracy), 3 undecided, 0 inverted brackets.
* **Binaries:** bit-exact with `-O0`/`-O2` on all 8 models; FMA contraction and
  fast-math move scores by < 1e-6 without changing a prediction. The audit also
  caught a real bug in the generated parser (subnormal inputs such as `1e-40` were
  rejected), now fixed.

The falsifier on its own (Guardian-APC+) detects 99.2% of oracle-observable
faults with 128 inputs versus 75.0% for random testing (McNemar p < 1e-4).

## How it works

* **Falsifier — Guardian-APC+**: inputs placed on every ReLU kink at any depth
  (Newton on the exact gradient), ordered by activation-pattern coverage, focused on
  what a rewrite changed, plus near-miss search.
* **Certifier**: float32-sound symbolic bounds (dot-product rounding bound γₙ),
  a bit-exact canonical form, **lockstep differential propagation** of
  Δ = candidate − original with an **exactness bit** per value (proves bit-identity)
  and symbolic Δ bounds, **divergence sources**, and branch and bound.
* **Falsify-or-certify loop**: static proof (zero evaluations) → Guardian-APC+ →
  certificate-guided branch and bound whose undecided boxes produce witnesses
  (centre, divergence-source solutions, gradient vertex).
* **Every link**: compiler passes, model edits, domain specialisation (neurons proven
  dead on the deployment domain removed, re-certified), compression severity
  brackets, and the compiled binary.

## Terminal tools (no website needed)

```bash
./build/Release/temper <model.mforge> [--data test.csv] [--out dir]   # deployment dossier
./build/Release/modelforge_studio          # interactive terminal view
./build/Release/modelforge_studio --demo   # every screen, non-interactive
./build/Release/modelforge_bench           # every number above (about 4 minutes)
./build/Release/modelforge <model.mforge>  # the compiler alone
```

Studio screens: **t** verdicts for every pass and bug, **c** a certified-region map
(a 2-D slice of input space coloured certified / refuted / undecided), **k**
compression brackets, **d** the deployment dossier, plus the compiler and Guardian
screens (pipeline, IR graph, neuron stability, coverage, fault arena, model diff,
shrink-and-check, benchmark). On Windows use `.\build\Release\temper.exe` and so on;
add `--ascii` if the terminal font lacks box-drawing characters.

## Build from the folder opened in VS Code

Open the integrated PowerShell terminal at:

```text
C:\Users\Sri vaishnavi\Compiler
```

Run these commands:

```powershell
cmake -S . -B build
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
.\build\Release\modelforge.exe .\ModelForge\review_2_core_implementation\models\iris_demo.mforge --out .\build\generated
```

Add `--dump-cpp` to print the generated `model.cpp` source in the terminal as
proof during the demonstration:

```powershell
.\build\Release\modelforge.exe .\ModelForge\review_2_core_implementation\models\iris_demo.mforge --out .\build\generated --dump-cpp --guardian-demo-bug
```

PowerShell needs `.\` before a local executable. The root `CMakeLists.txt`
forwards the build to the Review 2 implementation.

The Guardian demo deliberately changes ReLU to Sigmoid in a temporary graph.
Guardian rejects that candidate and writes `build/generated/counterexample.json`
with the input and both outputs. Real optimizations are checked separately;
`build/generated/optimization_certificate.json` lists pass decisions and probes.
The deliberately wrong graph is never emitted as C++.

Compile and run the generated C++ program:

```powershell
cmake -S .\build\generated -B .\build\generated_build -G "Visual Studio 17 2022"
cmake --build .\build\generated_build --config Release
.\build\generated_build\Release\generated_model.exe
.\build\generated_build\Release\generated_model.exe 1 2 3 4
.\build\generated_build\Release\generated_model.exe --csv .\ModelForge\review_2_core_implementation\models\iris_inputs.csv
```

The first run uses four zeros for the original demo. The second runs a real
four-feature input, prints all output scores, and predicts class 1. The
generated program rejects a wrong number of features or non-numeric input;
its `infer()` function in `model.h` can also be called from another C++ app.
The `--csv` form runs every numeric row in a file and prints a machine-readable
CSV with row number, predicted class, and each output score. The sample file
has two four-feature rows. Blank lines are ignored; a malformed row stops
processing with its line number. You can save the output with PowerShell:

```powershell
.\build\generated_build\Release\generated_model.exe --csv .\ModelForge\review_2_core_implementation\models\iris_inputs.csv > .\build\predictions.csv
```

For another input, replace `iris_demo.mforge` with `binary_sigmoid_demo.mforge`.
See [the research note](ModelForge/docs/research_contribution.md) for the
Guardian experiment and its limits.

The small Guardian fault-injection comparison prints a CSV table:

```powershell
.\build\Release\modelforge_guardian_eval.exe .\ModelForge\review_2_core_implementation\models\iris_demo.mforge
```

laptop. CMake alone cannot compile the project.

If Windows Application Control blocks a built `.exe`, the build succeeded but
that laptop needs administrator approval to run it. GitHub Actions builds and
runs the project independently on Windows and Linux. Each successful run also
attaches the generated C++ source, certificate, and counterexample as a
downloadable demo artifact.
