\section{Introduction}
Neural networks increasingly run on microcontrollers that have no floating-point unit and a few kilobytes of RAM. To get there, a model is compiled to integer code~\cite{jacob,tflm}:
\begin{itemize}
\item weights become 4- to 16-bit integers;
\item activations are rescaled with fixed-point multipliers and shifts;
\item dot products accumulate in 16- or 32-bit registers;
\item values outside the calibrated range saturate.
\end{itemize}
Each of these steps can change a prediction, and two can fail outright: an accumulator that is too narrow overflows, which is undefined behaviour in C, and a scale that is too small clips. Today the integer program is accepted when its accuracy on held-out data is close to the float model's. That check says nothing about the inputs a deployed device actually sees, and nothing about overflow.

Verification research studies the relationship between a network and a quantised version of it~\cite{reludiff,neurodiff,qebverif,ceg4n,qnnverif}, but analyses an \emph{idealised} quantised network. The program that runs is different: it rounds at specific points, approximates every rescaling by an integer multiplier and a shift, applies ReLU to the accumulator, saturates, breaks ties by index and can overflow. On the compiler side, fixed-point code synthesis~\cite{syfix} meets an output-error threshold, a weaker property than decision equivalence, and produces no evidence that a third party can check.

\emph{ForgeCert} closes this gap in the style of proof-carrying code~\cite{pcc}. It compiles a network to integer-only C99 and emits a certificate that the \emph{emitted C program}
(i)~never overflows on a declared input domain, and
(ii)~returns the float model's decision for \emph{every} input in each certified region around real samples.
A checker that shares no code with the compiler re-establishes both claims from the source model and the C file alone. The key idea is to use one abstract interpretation for three jobs at once: to \emph{prove} the generated code, to \emph{decide} its representation (scales, accumulator and multiply widths, which weights can be dropped), and to \emph{explain} failed proofs (which layer to make more precise). Every width in the program is therefore a discharged proof obligation, and the compiler can exploit facts that a conventional quantiser must not assume.

\textbf{Contributions.}
\begin{enumerate}
\item \textbf{Differential affine abstract interpretation of integer code} (\S\ref{sec:ai}). The float model and the integer program's error are tracked over shared noise symbols, with transfer functions for the bit-exact semantics of the emitted C: fixed-point requantisation, rounding, ReLU on the accumulator, \emph{saturation} and argmax tie-breaking. Dense layers, grouped convolutions, pooling and residual additions are handled uniformly as tap graphs, with an exact-where-possible transfer function for max-pooling.
\item \textbf{Proof-guided lowering} (\S\ref{sec:lower}): scales from proved ranges or from calibration data (with saturation modelled), \emph{modular accumulators} sized by the proved final sum, \emph{16-bit multiplies} where every product provably fits, and \emph{dead-input elimination}. Each is sound only because of a proof, and each is re-checked.
\item \textbf{Counterexample-guided precision tuning} (\S\ref{sec:cegar}) driven by \emph{error provenance} carried in the abstract domain, with a falsifier that turns failed proofs into real counterexamples, and with cost models for bytes or for cycles on an 8-bit microcontroller (measured, not assumed).
\item \textbf{An independent certificate checker} (\S\ref{sec:check}) that parses the emitted C, checks it against its own copy of the code template, re-proves the obligations and replays the split trees.
\item \textbf{An evaluation} on 12 trained models (tabular MLPs, MNIST and Fashion-MNIST MLPs and CNNs) with a cycle-accurate 8-bit microcontroller (\S\ref{sec:eval}).
\end{enumerate}
ForgeCert is part of the open-source ModelForge compiler (C++17). Its front end has a lexer/parser for a model language, a semantic validator with shape inference and symbol table, an SSA-style IR, and graph passes that are themselves validated by an existing per-pass validator (Guardian-APC+), so every stage from source to C carries evidence.

\section{Background and Related Work}
\textbf{Abstract interpretation of networks.} Interval bound propagation and zonotopes (DeepZ~\cite{deepz}, built on affine arithmetic~\cite{affine}) over-approximate a network's outputs on an input box~\cite{cousot}. ReluDiff and NeuroDiff~\cite{reludiff,neurodiff} propagate the \emph{difference} of two networks. QEBVerif~\cite{qebverif} bounds quantisation error for weights and activations and falls back to MILP. Henzinger et al.~\cite{qnnverif} verify bit-precise quantised networks with SMT. These works analyse a fixed pair of networks and generate no code. None models requantisation with integer multipliers and shifts, saturation, or the argmax of the deployed code.

\textbf{Precision tuning and code synthesis.} Precimonious~\cite{precimonious} and Daisy~\cite{daisy} tune floating-point or fixed-point precision against error bounds. SyFix~\cite{syfix} uses linear programming to choose fixed-point formats for network neurons under an output-error threshold. CEG4N~\cite{ceg4n} alternates a genetic search over bit widths with equivalence checking by a bounded model checker. ForgeCert differs in four ways:
\begin{itemize}
\item the property: decision equivalence on regions plus overflow freedom, for the emitted integer semantics;
\item the refinement signal: provenance carried by the abstract domain, not search;
\item the use of proofs to choose representations: modular accumulators, multiply widths, dead inputs;
\item the evidence: a certificate checked by an independent program.
\end{itemize}

\textbf{Deployment.} TensorFlow Lite Micro~\cite{tflm} and integer-only inference~\cite{jacob} calibrate per-tensor or per-channel scales on data and use int8 weights and activations with 32-bit accumulators. ForgeCert can certify exactly such programs (\emph{calibrated} scales) and compares against them.

\textbf{Trusting compilers.} Verified compilers~\cite{compcert} prove the compiler once. Translation validation~\cite{pnueli,necula} checks each run. Proof-carrying code~\cite{pcc} ships the proof with the code, so the consumer trusts only a small checker. ForgeCert follows the last model: finding a proof (search, splitting, refinement) happens in the untrusted compiler, and checking it is a linear replay.

\section{Limitations}\label{sec:limits}
\begin{itemize}
\item \textbf{Operators.} ForgeCert supports ReLU networks built from dense layers, grouped convolutions, batch normalisation, average and max-pooling and residual additions. Concatenation, attention and non-ReLU activations (sigmoid or tanh inside the network, ReLU6) need further transfer functions. Max-pooling must follow the ReLU and have no padding.
\item \textbf{Scale.} The analysis is dense in the number of noise symbols. Our largest model has 25k parameters and 784 inputs, which is typical for 8-bit microcontrollers but small for larger devices.
\item \textbf{Reference semantics.} The reference is the float model in exact real arithmetic, not its float32 execution.
\item \textbf{Rounding of the analysis.} Analysis and checker use double precision with outward slack rather than directed rounding.
\item \textbf{Excluded regions.} Regions on which the float model is not provably constant are excluded, and larger radii exclude many regions.
\item \textbf{Search.} The tuner is greedy. On the fine lattice it can miss a cheaper certified configuration that needs two coordinated changes.
\item \textbf{Latency model.} The cost model is for one microcontroller and one compiler.
\item \textbf{Independence.} The checker is independent code, but has the same author as the compiler.
\end{itemize}
